# tools context

Context-local rules for `tools/`. Repository rules live in `../AGENTS.md` and `../AGENTS/*.md`; this file links to them and never copies them. Rules for contexts: `../AGENTS/contexts.md`.

## Purpose

Standard tooling: the `standardctl.py` verifier and the owner work queue CLI `work_queue.py`, with the primitives they share.

## Invariants

- Every check is registered in `CHECKS` in `standardctl.py` with a stable finding id.
- Schemas in `Canonical/schemas/` are generated by `gen_schemas.py` and pinned by the inventory; never hand-edit them.
- Queue writes are owner-controlled; implementers never run `work_queue.py` write commands.

## Public Interface

- `standardctl.py`: `verify` (groups `policy`, `lean`, `security`), `doctor`, `init`, `worktrees`.
- `work_queue.py`: `next`, `guard --claim <owner/repo#n>`, and the logged owner writes (`move`, `limit`).

## Scoped Commands

Run from the repository root:

- Test: `python3 -m unittest discover -s tests -p "test_*.py"`
- Policy only: `python3 tools/standardctl.py verify --select policy`
- Lint: `python3 -m compileall -q tools tests`

## Do Not Touch

- `../Canonical/schemas/`: generated by `tools/gen_schemas.py`; regenerate, never hand-edit.
- `../.github/workflows/`: owned by the PR Gate; changes need an owner-authorized Issue.
